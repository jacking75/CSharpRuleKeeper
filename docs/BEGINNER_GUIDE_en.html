Check C# code with one standalone command.

CSharpRuleKeeper analyzes C# rules, identifies HBCS diagnostic locations, and creates Markdown repair guidance. It does not modify the project being checked.

CRKStartCommand referenceOptionsScriptsPractice

Check the execution contract first

Run the read-only doctor to inspect dotnet, installed SDKs, PowerShell, and the target's effective global.json. Repository development uses the .NET SDK 10.0.400 feature band with latestFeature roll-forward; targets use their own SDK.

powershell -NoProfile -ExecutionPolicy Bypass -File "C:\tools\CSharpRuleKeeper\build\Invoke-CSharpRuleKeeper.ps1" -Doctor -Solution ".\MySolution.sln"

The default check runs dotnet format whitespace --verify-no-changes without changing files. -Fix applies whitespace only and never runs naming, API, or external Code Fixes. Markdown and JSON are written together. Zero HBCS diagnostics is not completion unless JSON says analysisCompleted: true. Exit codes are 0 for pass, 1 for completed policy failure, and 2 for execution/configuration/incomplete analysis.

Gradual adoption
Review the presets guide and baseline contract. Presets are never auto-applied, and TreatWarningsAsErrors can fail a build on warnings. Rule exceptions, boundaries, fixes, and contract risks start at the rule documentation.

Start in four steps

Use the same flow for code you wrote yourself and code changed by a coding agent.

1. Locate the toolFind the local path of this repository.
2. Select the targetChoose a `.sln` or `.csproj` to check.
3. Create a reportRun the command and read the Markdown guidance.
4. RecheckCorrect the code safely and run the command again.

Run a check

powershell -NoProfile -ExecutionPolicy Bypass -File C:\tools\CSharpRuleKeeper\build\Invoke-CSharpRuleKeeper.ps1 -Solution .\MySolution.sln -OutputPath .\coding-agent-change-report.md
Expected result
A build containing errors exits with a non-zero code. This is expected. Read `coding-agent-change-report.md`, make safe corrections, and rerun the command until its HBCS diagnostic count is zero.

How to read the command

The command has four parts: start PowerShell, locate the tool script, select the target, and choose the report path.

PartMeaningWhat to change
powershellStarts Windows PowerShell.Leave it unchanged.
-NoProfileAvoids personal PowerShell profile settings.Leave it unchanged.
-ExecutionPolicy BypassApplies only to this process; it does not change the machine's permanent execution-policy setting.Leave it unchanged.
-File ...Invoke-CSharpRuleKeeper.ps1Path to the standalone checker.Replace C:\tools\CSharpRuleKeeper with your tool folder. Quote the whole path when it contains spaces.
-Solution .\MySolution.slnThe solution or project to check.Replace it with your `.sln` or `.csproj` path.
-OutputPath ...mdWhere to write the Markdown repair report.Choose any report name or folder. .\ means the current PowerShell directory.

Optional switches

SwitchUse it when
-FixYou have reviewed and approved formatting changes. It runs `dotnet format` only; it does not make semantic lint fixes.
-DefineConstants DEMONSTRATE_RULESYou need to enable a compile symbol, such as the included practice sample.
-ExplainEditorConfigYou want to show supported `personal_csharp_rules.*` options without running a check.

Configure and explain rules

Add custom options to the target project's `.editorconfig`. This is optional and does not create a project reference.

[*.cs]
personal_csharp_rules.method_lines_warning = 30
personal_csharp_rules.method_lines_error = 100
personal_csharp_rules.type_lines_warning = 300
personal_csharp_rules.type_lines_error = 500
personal_csharp_rules.file_lines_warning = 500
personal_csharp_rules.file_lines_error = 1000
personal_csharp_rules.max_line_length = 120
personal_csharp_rules.allow_magic_numbers = -1,0,1,2

Show every supported option, value format, default, and associated diagnostic:

powershell -NoProfile -ExecutionPolicy Bypass -File C:\tools\CSharpRuleKeeper\build\Invoke-CSharpRuleKeeper.ps1 -ExplainEditorConfig

Save the explanation to Markdown by adding -OptionsDocumentationPath .\CSharpRuleKeeper-editorconfig-options.md.

Practice with the included sample

The sample contains intentional violations that are excluded from the normal build. The following command enables them, intentionally fails, and creates a report with HBCS001 and HBCS002.

powershell -NoProfile -ExecutionPolicy Bypass -File .\build\Invoke-CSharpRuleKeeper.ps1 -Solution .\samples\SampleConsumer\SampleConsumer.csproj -DefineConstants DEMONSTRATE_RULES -OutputPath .\sample-practice-report.md
  1. Read the report.
  2. In `RuleViolations.cs`, change the public `Count` field into an encapsulated property.
  3. Rename `Ready` to `IsReady`.
  4. Run the same command again and confirm that the HBCS diagnostic count is zero.

Safety boundary

Do not change public APIs, serialization contracts, external protocol strings, or exception behavior merely to make diagnostics disappear. Use the report as guidance, inspect the surrounding code, and preserve behavior while correcting the rule violation.
